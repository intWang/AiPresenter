## Main Risks

1. Spanish package-local support may be misdocumented as runtime support.

   The docs can say Spanish localization is complete, Spanish aliases are broad,
   and unaccented Spanish prompts can route through package knowledge. They must
   still say `demo --language es` and `controller --language es` are unsupported
   until a runtime promotion cycle owns voice/provider/controller/profile and
   acceptance work.

2. Generated counts can drift if copied from Cycle126 handoffs.

   Durable docs should not manually inherit historical counts such as the old
   `87` aliases or `71` Q&A prompts. They also should not freeze today's `156`,
   `84`, `69`, `49`, or `34` without stating they came from fresh CLI reports.

3. Accent-insensitive matching can be overstated.

   Cycle126 folded Latin diacritics with canonical decomposition. It did not add
   fuzzy matching, stemming, semantic matching, transliteration, Japanese width
   folding, runtime Spanish voice support, or new YAML aliases.

4. Live RingCentral acceptance can be accidentally implied.

   Updating knowledge docs after better package localization does not create
   live click evidence. Evidence levels such as `Repo-tested`, `Observed`,
   `Accepted`, and `Blocked` must stay distinct. Manual acceptance still belongs
   in `acceptance-runs.md` before evidence levels are promoted.

5. Concurrent docs edits can be overwritten.

   `language-lifecycle.md`, `runtime-safety-routing.md`, and `source-index.md`
   are already modified in the working tree by another agent. Any follow-up
   docs refresh must read the current files and patch only the intended text.

6. `.coverage` can be accidentally staged.

   The workspace already has a modified `.coverage`. A docs-only refresh should
   not run coverage-producing tests unless needed, and must never stage that
   artifact.
