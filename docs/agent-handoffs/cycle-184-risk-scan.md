# Cycle 184 Risk Scan: Answer Source Observability

Date: 2026-05-17

## Findings

- P2 privacy sentinel gap: the first entrypoint logging test used `participants`, which also appears inside the logged entrypoint id. The corrected test uses `show network quality` so the full raw prompt can be asserted absent.
- P2 compatibility: adding `answer_source=<enum>` changes the successful log shape. This is acceptable for tolerant parsers but should be recorded for any future exact-message consumers.
- Error path should remain minimal. Failed calls do not have a reliable response source and exception text may contain private content.
- `.coverage` is generated by verification and must remain unstaged.

## Safe Values

`answer_source` values are bounded tokens:

- `qa`
- `entrypoint`
- `presenter_meta`
- `no_match`

They do not contain user question text, answer text, UI labels from a live meeting, or exception messages.

## Required Before Commit

- Focused logging tests with `--no-cov`.
- Full `pytest`, `ruff`, and `mypy` gate.
- `git diff --cached -- .coverage` must be empty.
